# 「字幕載不進來」的完整歷史

這份文件按時間順序列出每一次「字幕沒出現」的**真正原因**、修法與驗證方式。
每個原因都是先在正式站觀察到症狀，再回頭找出成因，而不是猜測。

---

## 1. Windows 桌面版完全沒有送出任何請求

**症狀**：Arch Linux 與 Android 正常，Windows 桌面版裝了之後伺服器完全沒有收到請求。

**真正原因**（兩個獨立的 manifest 問題）：

| 欄位 | 問題 |
| --- | --- |
| `idPrefixes: ["tt"]` | 這個欄位限制「用戶端只會為了哪些 id 來問你」。設成 `["tt"]` 之後，任何非 IMDb id 的內容（本機檔案、其他目錄的 id）根本不會被送過來，症狀正好就是「裝了卻沒有請求」。 |
| `behaviorHints.configurationRequired: true` | 強迫每一次安裝都必須先經過 `stremio://` 連結。那個通訊協定在某些 Windows 安裝（尤其 Microsoft Store 版）沒有註冊成功，按下之後毫無反應，而 Stremio 不會顯示任何錯誤。 |

**修法**：兩個欄位都移除。字幕外掛沒有理由限縮 id：查不到的 id 只會得到空清單。

**另外**：最保險的安裝方式是**複製 Manifest 網址、貼進 Stremio「附加元件」頁的搜尋框再按 Enter**，這條路完全不經過 `stremio://`。

## 2. 面板說「沒有收到請求」，但其實有

**症狀**：設定頁的三個診斷面板全部空白或顯示「還沒有收到任何來自 Stremio 的請求」。

**真正原因**（兩個）：

1. **桌面版不會自稱 Stremio。** 它送出的是 `QtWebEngine/5.15.2 Chrome/83…`，字串裡完全沒有 “stremio”。「安裝進度」原本用 `stremio` 去比對 User-Agent，所以桌面版明明正在要字幕，那一項卻顯示沒有請求。
2. **面板用相對路徑抓資料。** `fetch('api/requests')` 是對**頁面**解析的，所以在 `/<設定>/configure` 這頁會變成 `/<設定>/api/requests` 而 404，三個面板全部空白——看起來就跟「沒有任何請求」一模一樣。

**修法**：改由伺服器判定用戶端名稱（`Stremio 桌面版（Windows）`）並回傳；面板改用絕對路徑，伺服器也同時接受舊的相對路徑，避免瀏覽器快取的舊頁面繼續給出錯誤結論。

---

## 3. 上游 OpenSubtitles v3 進入維護，下載全部失敗

**症狀**：清單看得到字幕，選了卻出現 `no tracks`。伺服器日誌是 `/srt/…` → **502**，並印出 `字幕下載失敗（HTTP 469）`。

**真正原因**：上游的**下載**端點 `subs5.strem.io` 回傳 HTTP **469**，內容是一頁 HTML：

> `<pre>Site will be online soon. We are doing some necessary backups and upgrades.</pre>`（附 `retry-after: 300`）

它的**搜尋**端點仍然正常，所以從清單完全看不出來。我們的伺服器丟出錯誤 → 502 → 播放器只說 `no tracks`。

**修法**（三層）：

1. **下載失敗時換來源**：重新查詢所有已設定的來源，找出**同一語言**的其他檔案再試（最多 3 個），成功時記錄 `downloadFailovers`。
2. **HTML 一律視為失敗**：維護頁可能配著 200 送出。字幕至少會有一行時間碼，所以任何長得像網頁的回應都在解析前就被擋掉，而不是被解析成 0 句再給觀眾看 `no tracks`。
3. **失敗時回一份合法的單句字幕**，把原因寫在畫面上，例如
   `[OpenCC 字幕] 這個字幕無法產生：字幕下載失敗（HTTP 469）`。
   以前回 502，播放器只會說 `no tracks`，看不出是哪裡壞的。

## 4. 用戶端中途放棄的請求完全沒有紀錄

**症狀**：想知道「播放器到底有沒有來要字幕、要了之後是不是等太久」，但紀錄裡什麼都沒有。

**真正原因**：只在回應 `finish`（完成）時寫紀錄。**用戶端中途放棄永遠不會觸發 `finish`**，所以「有來要、但被放棄」正好是唯一不會留下痕跡的情況。

**修法**：同時在 `close` 時寫紀錄，並標記「中斷」。

---

## 5. 來源給的是「你電腦上的網址」

**症狀**：某一筆字幕列得出來、選得下去，但一定失敗。

**真正原因**：SubSense 回傳的是

```
http://127.0.0.1:11470/subtitles.srt?from=<真正的網址>
```

`11470` 是 **Stremio 本機串流伺服器**——只有正在播片的那台電腦才有這個位址。從伺服器端抓它沒有任何意義。

**修法**：把真正的網址從 `from=` 拆出來使用；指向 Stremio 本機伺服器、又沒有 `from=` 可拆的就直接丢掉。**其他** loopback 位址保持不動，因為從伺服器端無法分辨它是不是真的在本機。

## 6. `.ass`／`.ssa` 被當成 SRT 送出（最關鍵的一個）

**症狀**：下載**成功**（HTTP 200）、檔案大小也正常，播放器卻說 `no tracks`；同一筆的中文版本則變成「Google 翻譯失敗（HTTP 400）」的錯誤訊息。

**真正原因**：SubSense 給的是 **Advanced SubStation**（動畫圈常見的 SubsPlease `.ass` 檔），而且**標成 `.srt`**。它不是「標點不同的 SRT」：

- 字幕藏在 `Dialogue:` 行裡，欄位順序由 `Format:` 行宣告
- 時間是**百分秒**（`0:00:00.95`），不是毫秒
- 文字夾著 `{...}` 樣式指令與 `\N` 換行
- 還有 `Comment:`（作者註解）與 `{\p1}…{\p0}`（向量繪圖資料）

照原樣當 SRT 送出，播放器在整份檔案裡**找不到任何一句**，於是回報 `no tracks`；翻譯那條路更慘，它把腳本標頭 `[Script Info]` 當成字幕送去翻譯，Google 直接回 400。

**修法**：依**內容**判斷（不能看檔名，來源會說謊）並先轉成 SRT，再走原本的轉換／翻譯流程。`Comment:` 不當字幕、繪圖資料不當文字。

**驗證**（正式站，同一筆字幕）：

| | 修好前 | 修好後 |
| --- | --- | --- |
| 英文 `.ass` | 開頭是 `[Script Info]`，**0 句** | **326 句**，`00:00:07,870 --> 00:00:10,330  Congratulations, Mother.` |
| 它的中文版 | 「Google 翻譯失敗（HTTP 400）」 | **326 句**，`恭喜你，媽媽。` |

## 7. 集數編號不一致：來源明明有字幕，清單卻是空的

**症狀**：某部動畫的某一集「有些字幕載不進來」，而且清單裡只有一個來源的字幕；
選了之後顯示 `字幕下載失敗（HTTP 500）`。

**真正原因**（兩個問題疊在一起）：

1. **播放器用絕對集數發問。** 它要的是 `tt26743760:1:49`——「第 1 季第 49 集」。
   但這部作品每季只有 24 集，所以第 1 季根本沒有第 49 集。這是動畫圈的
   **絕對集數**慣例：整季連續編號，第 49 集其實是**第 3 季第 1 集**
   （S1 24 集 + S2 24 集 = 48，所以 49 就是 S3E1）。
2. **兩個正常來源都按季編號。** `opensubtitles-v3` 與 `SubSense` 對 `:1:49` 回
   **0 筆**（日誌與直接查詢都確認），所以清單裡只剩下唯一一個「剛好也吃絕對集數」
   的來源——而它的下載端點正在回 **HTTP 500**。

於是：**唯一配得上這個編號的來源壞了，而兩個能用的來源因為編號對不上，從來沒被問到。**
備援也救不了：它只在同一個 id 底下找替代檔案，而其他來源在那個 id 底下什麼都沒有
（`failovers: 0`）。

**驗證**：

| | 修好前 | 修好後 |
| --- | --- | --- |
| `:1:49` 的清單 | 只有壞掉的來源 | **6 筆**（3 筆繁體中文＋英文，來自 opensubtitles-v3） |
| 中文那筆下載 | `字幕下載失敗（HTTP 500）` | **365 句**，`00:00:47,547 --> 00:00:48,715  此藥` |

**修法**：新增 `src/episodes.js`，用 Cinemeta 的集數表把絕對集數換算成季／集，
**兩種編號都查**，清單與備援都適用。三個安全邊界：

- 只有當**該季存在、但集號超出該季範圍**時才換算。季本身不存在的（例如 metadata
  還沒更新的新一季 `:4:1`）**不猜**，否則會被錯誤地對應到第 1 季第 1 集。
- **第 0 季（特別篇）不列入絕對集數**，否則每一集的對應都會被特別篇的數量推移。
- Cinemeta 查詢失敗時**不寫入快取**，避免一次網路抖動把「這部沒有集數」記住六小時。

## 排除掉的（確認「不是」原因）

查錯方向會浪費很多時間，所以這些也記錄下來：

- **manifest 本身**：用 Stremio 官方的 `stremio-addon-linter` 驗證 → **通過，0 錯誤**。
- **字幕回應格式**：用 Stremio 官方的 `stremio-addon-client` 抓 → **6 筆全部解析成功**。
- **語言代碼 `zht`**：上游 OpenSubtitles v3 外掛也用 `zht`，沒有證據顯示它會導致失敗。
- **`Content-Type`、CORS、快取標頭**：都正確。

**兩次是我自己的測試腳本出錯，不是外掛的問題**，也一併記錄以免重蹈覆轍：

1. 存下來的網址檔被折成兩行，Node 的 `.replace(/…$/)` 少了 `m` 旗標而沒去掉尾綴，結果抓到錯的網址，誤判成「manifest 回傳字幕」。
2. 統計串流端點需要 `id` 參數；沒帶 `id` 時它立刻 404，所以「中斷的請求沒被記錄」是測試寫錯，不是程式錯。

## 現在的行為

一筆字幕要送達播放器，會依序經過：

1. 列出（多來源聚合、去重、版本比對、標記最佳解）
2. 使用者選擇 → 下載（失敗時換來源；HTML 一律視為失敗）
3. **格式正規化**（ASS/SSA → SRT；編碼偵測）
4. 轉換（OpenCC）或翻譯（Google，缺字幕時）
5. 時間軸校正（25 ↔ 23.976 fps）
6. 送出；**任何一步失敗都會回一份合法的單句字幕說明原因**，而不是讓播放器只說 `no tracks`

診斷入口都在設定頁：**「最近收到的字幕請求」**、**「所有進來的請求」**（含用戶端名稱與「中斷」標記）、**「安裝進度」**。
